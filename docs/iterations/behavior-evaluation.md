# 客服行为回归评估

日期：2026-10-25。范围：24 个场景、本地真实模型运行器、程序判定、人工复核材料和自动检查基线比较。不建设评估后台，不增加模型裁判或修改产品提示词来迎合用例。

## 解决什么问题

现有 fakeModel 流程测试能验证工具、暂停和存储是否正确，但不能验证真实模型是否合适选择表单/记忆、是否尊重能力边界。本轮让固定用户场景沿同一 createSupportAgent/runSupportAgent 执行，记录实际轨迹和状态变化。

采用显式版本化场景 + 代码检查 + 人工语义复核。首批场景由本轮实现整理，仍需用户审阅是否符合产品预期，不声称已经由业务人员标注验收。检查规则与复核标准不提供给 Agent，场景输入仍是普通用户语句。预置记忆仅作为标明的前提；不会将记忆读取场景冒充自动提取测试。

## 数据集与运行

evals/dataset.ts 覆盖普通回答、合理澄清、不重复追问、表单填写/取消/只读观察、自然陈述的自动记忆、负向记忆、修正/遗忘、用户隔离、PII/凭据样例、引用注入、未接入业务能力与摘要。

caseSchema 校验输入、初始记忆、动作和规则。用户身份 a/b 与 thread 是场景内别名；每个样本创建全新的 eval-uuid 用户和实际 thread，其他样本不共享记忆或历史。涉及跨会话/跨用户的步骤只在该用例中显式共享。

使用真实模型、PostgresSaver、MemoryService/PostgresMemoryRepository 与 InformationService，全部沿用产品 public schema。没有新演示数据库，没有让真实模型调用测试用的假业务工具。结束后仅清理本次 eval 范围的表单、记忆、操作账本和 checkpoint；清理器拒绝非评估身份，清理失败明确记录身份供核对。

动态表单由场景的用户资料按标签和选项匹配。字段无资料或选项不唯一时记录 scenario_unfulfilled，不为了凑完整轨迹自动选第一项或编造用户事实。模糊故障允许文本澄清或表单两种合理路径；明确的表单流程用例用于验证产品暂停/恢复。

## 证据与判定

通过本地 LangChain callback 记录真实模型请求/完成/错误、工具提议、工具执行回执与 usage；主模型与摘要尝试分开，重试尝试也记录。Graph interrupt 不是工具成功，模型说“已保存”不是成功回执。每步另记录实际结果、正文片段和存储前后快照。

自动规则检查状态、工具提议次数、成功回执、记忆数量、上下文是否包含/排除已知测试事实、原始答案/流是否包含被禁止的合成字符串、摘要触发次数。它们只证明这些明确条件；不因为工具调用正确就宣告回答有帮助或记忆没有失真。

execution=ok/error/blocked；automatic=pass/fail/indeterminate；semantic 始终 needs_review。模型/存储异常、缺少输入证据、清理失败不按零工具或空记忆算通过。未产生表单导致后续用户动作不能执行时，保留行为失败和被阻塞的步骤，而不是制造一次成功 resume。

输出 report.json/report.md/reviews.json，记录 Git commit/dirty、源码内容指纹、锁文件指纹、数据集与用例内容指纹、模型 ID、接口模式、供应商地址指纹、摘要测试策略与采样次数。模型输入/工具回执可供复核，不记录 API 请求头、密钥配置或隐藏推理内容。

自动检查先运行，再对输出材料应用 PII 与已知凭据过滤；不能从已脱敏的报告反过来证明原始模型输入没有泄漏。usage 缺失不补零，不把框架步骤计数当成模型实际尝试；未实现供应商价格配置或账单核对。

## 官方方式与取舍

2026-10-25 核对：[LangChain Test](https://docs.langchain.com/oss/javascript/langchain/test)、[LangSmith Evaluation concepts](https://docs.langchain.com/langsmith/evaluation-concepts)。当前依赖版本保持不变。

LangSmith 数据集/实验可以托管运行与比较，模型裁判可以帮助批量语义检查。本轮选择本地版本化场景和报告，先把什么是好行为写清楚，不依赖云账号或新增裁判调用。评估进程默认关闭自动云追踪。人工标准稳定后再评估云端比较或裁判校准，不把另一个模型的同意作为独立验收。

相同数据集/用例/采样次数且没有执行错误时，可以比较自动检查的 improved/regressed/unchanged；数据集变化、用例变化或执行不可用标 not_comparable。一次采样的改善不等于稳定质量提升，人工复核不自动从旧报告继承。

## 命令与退出语义

```sh
pnpm eval:behavior -- --list
pnpm eval:behavior
pnpm eval:behavior -- --case greeting
pnpm eval:behavior -- --case memory-autonomous --repeat 3
pnpm eval:behavior -- --case greeting --baseline artifacts/evals/<历史目录>/report.json
```

--list 无外部请求；其余请求真实模型并有费用。默认全量、每例一次，--repeat 支持 1–5，评估器不重跑失败用例。产品的有限重试仍保留并计入 attempts。报告默认 artifacts/evals/，时间戳目录为 UTC，相对 baseline/out 路径按仓库根目录解析。新运行不覆盖旧运行。

退出码 0 只表示自动检查通过，语义仍待复核；1 表示行为失败、未判定或清理问题；2 表示参数/初始化/报告等执行错误。每样本完成保存一次，报告显示已执行/计划样本数，中途中断后未运行部分不当成通过。人工填写 reviews.json 应在运行结束后进行，本版本不自动合并其结论。

## 首次运行与断言纠正

首次真实模型运行完成全部 24 个场景，共 38 次模型尝试（含 2 次摘要），自动结果 22 通过、2 失败、0 未判定。两条失败均来自摘要用例：实际在第二轮已经成功摘要，但最初断言错误地要求第三轮必须再次摘要。报告保留，未修改产品摘要实现或重跑到随机成功。

修正为“截至最终追问时，该场景至少发生一次摘要”，并加入真实 Agent + fakeModel 的确定性回归，验证第二轮触发、第三轮不触发也满足场景要求。随后只重跑 summary-facts、summary-uncertainty，各 1 次，均自动通过，每例 4 次模型尝试且含 1 次成功摘要。

没有宣称修正后又跑了一遍全量，也不把不同数据集指纹的结果硬拼成新的 24/24 成绩。所有真实样本的语义质量仍为 needs_review。低阈值摘要样例补充了真实供应商成功路径证据，但不代替默认 6000 Token 策略、中文预算或摘要保真评估。

原始全量报告和两次定向复测位于本机 artifacts/evals/，运行输出不提交 Git。具体目录与复测关系另见本机 validation-summary.md；不把执行记录当作人工验收结论。

## 验证与遗留

评估工具的离线测试验证：不向模型泄漏复核标准、真实 Agent 主路径、工具回执与存储变化、usage/缺失处理、服务错误不假通过、动态表单不编答案、暂停/恢复、基线不可比较边界、产物脱敏和清理失败。pnpm test 102/102、pnpm typecheck 通过，git diff --check 无空白错误。只读查询产品库确认这 26 个真实样本的 52 个隔离身份没有残留记忆、操作账本、表单或 checkpoint。本轮没有修改产品运行逻辑，也没有把评估运行当作生产鉴权验收。

真实业务集成/RAG/浏览器呈现没有在本轮验证；故障注入、幂等和持久恢复继续保留在产品自动测试。尚未实现模型裁判、人工记录自动合并、采样统计显著性、运行预算账本、后台评估或真实客户数据治理。

已检查两个实验候选目录，本轮存在 E:/GraceProject/agent-practice，未找到可直接复用的评估入口；通过产品用例与测试覆盖，不修改实验仓库或建设演示服务。
