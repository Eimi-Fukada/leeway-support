# 源码职责整理

日期：2026-10-23。仅调整结构，不新增业务能力，不改数据库数据结构。

## 问题与契约

src 根目录九个文件，终端一次输入需要阅读 chat/cli-run/cli-options，职责虽小但跳转过多。目标是让同一职责的修改集中，输入、输出、错误传播、thread 恢复和连接生命周期保持原样。

## 方式、替代与取舍

按职责组织 Module，将紧密协作的终端逻辑合并，保留两处真实可替换 Seam：模型/检查点注入，以及执行事件/终端输出。这是本项目基于现有调用关系的判断，不声称目录布局有统一行业标准。本轮没有变更框架 API 或版本，继续沿用既有迭代中核实的机制。

全部合成一个文件可以减少文件数，但会把终端与模型、数据库及 Graph 执行耦合；只新建目录而不合并则仍需频繁跳转。本轮从九个文件收敛为七个，cli 的三个文件合成一个，agent/config 内按独立职责保留文件。没有新增接口层、barrel 或转发文件。

后续若 cli/chat.ts 内部出现独立增长的复杂功能，再按实际变化拆分；不为未来 HTTP、工具或记忆提前建空目录。

## 调用链与学习覆盖

index.ts → config/model.ts + config/checkpoint.ts → agent/agent.ts → cli/chat.ts。

每轮输入在 cli/chat.ts 内完成参数/会话/展示组织，调用 agent/run.ts 执行流；执行函数不导入 CLI 或真实配置，仍可使用 fakeModel/MemorySaver 独立验证。env.ts 移到 config 后，将环境文件定位同步改为 ../../.env。

已有 tests/ 继续独立存放，保持原有测试断言，只更新导入。测试名称按场景保留，不要求一个实现文件必须对应一个测试文件。此轮属于结构调整，不新增 Agent 知识点或学习仓库演示。

## 验证与遗留

调整前：23 个离线测试与类型检查通过。

调整后验证：`pnpm test` 23/23 通过；`pnpm test:postgres` 3/3 通过（真实数据库跨进程恢复、连接失败、读取失败）；`pnpm typecheck` 通过。通过根 `pnpm start -- --debug` 接收 /exit 正常退出，确认移动后的环境文件路径和数据库初始化可用。

确定性流程与真实存储分别通过；未请求真实模型，也未运行真实业务集成。本轮复用既有测试，不新增镜像实现的测试。`git diff --check` 无空白错误。

当前取消、并发、长期记忆及用户授权等能力仍沿原路线逐步推进，本次整理不代表这些已经实现。
